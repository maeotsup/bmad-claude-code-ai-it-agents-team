# Propose — Async Client Communication

Run the ANALYZE and DESIGN stages, then post the results as GitHub issue comments
for asynchronous client review. The client reviews and responds on the issue at their
own pace. Use `/resume` to continue after client feedback.

This enables non-technical stakeholders to participate in the planning process
through GitHub without needing CLI access.

## Steps

### Step 1: ANALYZE

1. Load project config from `_bmad/config/config.yaml`
2. Verify `async.enabled: true` in config. If not, inform user to enable it via config.
3. Fetch the issue: `gh issue view $ARGUMENTS --json title,body,labels,comments`
4. Create feature folder: `_bmad-output/<issue>-<slug>/`
5. Create STATE.yaml with `workflow: propose`, `state: planning`, `stage: analyze`
6. Invoke the **analyst** (Anna) agent to produce requirements
7. Save to `_bmad-output/<issue>-<slug>/requirements.md`

**GATE**: Show requirements to the local user for sanity check.
- **[C] Continue** → post to GitHub and proceed to design
- **[E] Edit** → adjust before posting
- **[S] Stop** → abort without posting

**HALT**: Wait for user selection before proceeding.

### Step 2: DESIGN

1. Invoke the **architect** (Indrek) agent to produce the architecture plan
2. Save to `_bmad-output/<issue>-<slug>/architecture.md`

**GATE**: Show design to the local user for sanity check.
- **[C] Continue** → post to GitHub
- **[E] Edit** → adjust before posting
- **[S] Stop** → abort without posting

**HALT**: Wait for user selection before proceeding.

### Step 3: POST TO ISSUE

1. Format the requirements and architecture as a single GitHub comment:
   ```
   ## Proposed Plan

   ### Requirements
   <formatted requirements summary — business-level, no file paths or internal details>

   ### Approach
   <formatted design summary — high-level approach, key decisions, estimated complexity>

   ### Questions
   <any open questions from analysis or design>

   ---
   *Reply to this comment with feedback or approval. Signals: LGTM, Approved, Looks good.*
   *Generated by AI team — run `/resume <issue>` to continue after review.*
   ```
2. Post via `gh issue comment <number> --body "<formatted>"`
3. Add label: `gh issue edit <number> --add-label "awaiting-client-review"`
4. Update STATE.yaml: `state: awaiting_review`, `stage: proposed`

## Completion

Report to the user:
- Proposal posted to issue #<N>
- Link to the comment
- Label `awaiting-client-review` added
- Next step: wait for client response, then run `/resume <issue>` to continue
- Artifacts saved in `_bmad-output/<issue>-<slug>/`
